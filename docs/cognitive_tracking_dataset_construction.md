# 认知跟踪 Benchmark 方案文档

## 1. 文档目标

这份文档用于明确我们准备构建的认知跟踪 benchmark 方案，目标是支持后续：

- 与组内老师和同学直接讨论
- 对标视频大模型、多模态大模型评测工作的常规做法
- 指导数据集整理、关键帧标注和评测实现

这份 benchmark 的核心定位不是重新定义目标跟踪，而是顺着目标跟踪任务的发展脉络，在 `短时跟踪`、`长时跟踪`、`全局跟踪` 三类任务上，系统评测 VLM 的复杂认知能力。

---

## 2. Benchmark 的核心立意

传统跟踪 benchmark 主要评测的是定位性能，例如 Success、Precision、AUC 等。这些指标能够衡量“框得准不准”，但无法回答以下问题：

- 模型是否知道当前目标还在不在
- 模型是否能区分遮挡、出视野和真正消失
- 模型是否能在序列推进中维持目标身份的一致理解
- 模型是否具备场景变化下的认知记忆和重定位能力

而这恰恰是视觉大模型相较传统 tracker 最值得研究的部分。

因此，我们的 benchmark 目标不是只比较大模型的 bbox 预测能力，而是要评测：

- `目标状态认知能力`
- `环境状态认知能力`
- `序列认知记忆能力`

这三类能力与我们当前的认知链是对齐的：

- 看见什么
- 判断目标是否还在
- 理解环境变化
- 维持跨时间的目标记忆
- 在后续帧中做一致性的认知决策

---

## 3. 方案设计原则

### 3.1 遵循目标跟踪任务的发展趋势

我们不脱离现有 tracking community 的任务定义，而是沿着较清晰的发展路径组织 benchmark：

- `短时跟踪`
- `长时跟踪`
- `全局跟踪`

这三类任务覆盖了从局部连续定位，到长时间身份维持，再到弱连续性甚至全图搜索的能力跨度，适合系统考察 VLM 的认知跟踪能力。

### 3.2 使用已有公开数据集，不先做新采集

第一阶段 benchmark 完全可以建立在已有公开数据集上。

这也是视频大模型、多模态大模型评测工作的常见做法：

- 不一定重新采集原始数据
- 更常见的是基于已有公开数据重组任务
- 补充派生标注、统一协议和新指标
- 用一个统一 benchmark 去比较多个模型

因此，我们当前不需要先做大规模视频采集，而是需要：

- 选好三类任务各自的代表数据集
- 为它们补关键帧标注
- 派生认知状态标签
- 设计统一评测格式

### 3.3 用关键帧评测减轻 VLM 推理负担

如果直接逐帧调用大模型，成本和速度都不可接受，也不利于后续做多模型横向评测。

因此，benchmark 第一版采用：

**稀疏关键帧认知跟踪评测**

关键帧设计有两个作用：

- 降低大模型推理成本
- 更真实地考察模型的认知记忆与跨时间推理能力

如果模型只能在逐帧密集输入下工作，它更像是在做局部连续跟踪；  
如果模型在稀疏观测下仍然能维持目标身份与状态判断，它才更接近“认知跟踪”。

---

## 4. Benchmark 的总体结构

我们准备将 benchmark 分成三个子任务，每个子任务选一个代表性数据集。

### 4.1 短时跟踪子任务

目标：

- 评测模型在较短时序范围内的目标识别与状态判断能力
- 重点看短期遮挡、相似物体干扰、轻度视角变化下的认知稳定性

要求数据集具备：

- 典型 SOT 结构
- 目标框标注清晰
- 场景相对连续
- 适合建立短时关键帧版本

### 4.2 长时跟踪子任务

目标：

- 评测模型在长时间视频中的身份持续认知能力
- 重点看 absent、occlusion、reappearance、长时间外观变化

要求数据集具备：

- 视频时长较长
- 目标缺失和重现情况丰富
- 具有较强的挑战属性标注

这一类任务是认知跟踪 benchmark 的核心部分。

### 4.3 全局跟踪子任务

目标：

- 评测模型是否具备弱连续性条件下的全图搜索与目标重识别能力
- 重点看场景跳变、位置先验失效、目标重新出现在远距离区域时的能力

要求数据集具备：

- 更弱的局部运动连续性
- 更强的全局搜索需求
- 更适合检验 VLM 的场景级推理能力

这部分任务与传统局部搜索式 tracker 的差异最大，也最能体现 VLM 的潜在优势。

---

## 5. 数据集选择原则

我们不是简单追求“最流行的数据集”，而是让三个子任务各自有明确角色。

### 5.1 选择原则

每个任务的数据集应满足以下条件中的大部分：

- 公开可获取
- 社区已有一定使用基础
- 有可靠的 bbox 标注
- 有足够多的困难场景
- 能支持关键帧稀疏评测
- 能与认知状态标签建立映射

### 5.2 角色化选择

推荐按角色来选，而不是一开始把名字写死：

- 一个代表 `短时跟踪`
- 一个代表 `长时跟踪`
- 一个代表 `全局跟踪`

这样做的好处是：

- 方案更清楚
- 后续调研相关文章时更容易对齐
- 即使具体数据集有调整，benchmark 的框架也不需要重写

### 5.3 当前建议

从现有基础出发，长时跟踪部分优先考虑 `MGIT`。  
短时和全局部分可以在后续调研后再最终敲定，但原则上仍应服务于三个任务层次，而不是只为了补数量。

---

## 6. 数据集构建方式

### 6.1 第一阶段只做“关键帧标注增强”

我们的 benchmark 第一阶段不重新采原始视频，不重做完整 bbox 标注，而是：

- 直接使用原始公开数据集的视频和目标框
- 对每个数据集构建关键帧版本
- 补充或派生认知评测所需标签

因此，从工程角度看，这个 benchmark 的主要数据构建工作包括：

- `关键帧筛选`
- `状态标签映射`
- `环境标签映射`
- `序列记忆评测单元构建`

### 6.2 为什么只做关键帧标注

这样做有几个直接好处：

- 成本可控
- 可以快速扩展到多个 VLM
- 易于复现
- 符合很多大模型评测工作的典型流程

更重要的是，关键帧评测本身就能引入新的研究问题：

- 稀疏观测下目标是否还能被认出
- 中间帧缺失时记忆是否还能维持
- 环境变化后是否还能做出一致判断

### 6.3 关键帧构建原则

关键帧不应只是简单等间隔采样，而应优先覆盖以下类型：

- 场景明显变化帧
- 目标状态变化帧
- 遮挡开始和结束帧
- 目标消失与重现帧
- 容易引发误识别的干扰帧

这样构建出来的关键帧子集，才能真正服务于认知能力评测，而不是只服务于降采样。

---

## 7. 统一任务输入输出

为了支持多个视觉大模型统一评测，benchmark 必须统一输入输出格式。

### 7.1 输入形式

每个评测样本至少包含：

- 初始目标参考
- 历史关键帧上下文
- 当前待判断帧
- 可选的语言描述或记忆摘要

在不同 tracker 实现中，输入可以是：

- 两图形式
- 三图形式
- Mosaic 历史拼接形式

但 benchmark 层面应统一抽象为：

**目标参考 + 时序上下文 + 当前帧**

### 7.2 输出形式

统一要求模型输出：

- `bbox`
- `target_status`
- `environment_status`
- `confidence`
- `reasoning` 或 `tracking_evidence`

如果后续要评测记忆能力，还可以额外要求：

- `memory_update`

这样做的原因是：

- 便于多模型比较
- 便于做自动解析和打分
- 便于后续构造训练监督数据

---

## 8. 我们要新增的评测维度

这是 benchmark 的核心创新部分。

### 8.1 目标状态评测

我们引入 `Target State Evaluation`，用于评测模型对目标当前状态的认知判断能力。

建议状态空间为：

- `normal`
- `partially_occluded`
- `fully_occluded`
- `out_of_view`
- `disappeared`
- `reappeared`

这一维度评测的问题是：

- 模型是否知道目标当前是否可见
- 模型是否能区分不同不可见原因
- 模型是否能判断目标是否重新出现

这部分不再是定位精度问题，而是标准的认知判断问题。

### 8.2 环境状态评测

我们引入 `Environment State Evaluation`，用于评测模型对当前跟踪环境的理解能力。

建议环境标签空间为：

- `normal`
- `low_light`
- `high_light`
- `motion_blur`
- `scene_change`
- `viewpoint_change`
- `scale_change`
- `crowded`
- `background_clutter`

这一维度评测的问题是：

- 模型是否能识别影响跟踪的外部因素
- 模型的环境判断是否与实际困难源一致
- 模型失败时，是否至少能“知道自己为什么难”

### 8.3 序列认知记忆评测

这是我们还可以进一步提出的一个关键维度，可以命名为：

- `Sequential Cognitive Memory Evaluation`
- 或者 `Temporal Cognitive Memory Evaluation`

这一维度用于评测模型能否在一个序列内维持目标身份和状态认知的一致性。

它不是单帧分类，也不是简单定位平均值，而是关注：

- 目标身份理解是否连续稳定
- 目标消失前后的判断是否自洽
- 目标重现时是否能基于历史记忆正确恢复
- 模型输出的 reasoning / memory update 是否前后一致

这个指标非常关键，因为它直接对应“认知链”中的记忆环节。

---

## 9. 序列认知记忆能力怎么评测

这部分需要单独设计，不宜只沿用传统 tracking 指标。

可以考虑从以下几个方向构建：

### 9.1 重现恢复能力

当目标经历 absent / disappeared 后重新出现时，评测模型是否能够：

- 判断这是同一个目标
- 恢复正确状态
- 在较少关键帧条件下重新定位成功

这本质上考察的是记忆驱动的重识别与恢复能力。

### 9.2 状态转移一致性

将一段序列中的状态判断连起来，评测是否符合合理的时序逻辑，例如：

- `normal -> partially_occluded -> fully_occluded -> reappeared`
- `normal -> out_of_view -> reappeared`

如果模型频繁出现不合理跳变，例如：

- 前一帧说 `disappeared`
- 下一帧又无依据地变成 `normal`

说明它缺乏稳定的序列认知。

### 9.3 记忆一致性

如果模型输出 `memory_update` 或 `tracking_evidence`，可以进一步检查：

- 对目标外观的描述是否稳定
- 对目标运动趋势的判断是否连续
- 对场景变化的判断是否和后续决策一致

这部分可以先做规则化评测，后续再探索更复杂的语义一致性打分。

### 9.4 稀疏条件下的性能保持

把逐帧版本和关键帧版本进行对比，评测模型在稀疏输入下的性能退化程度。

如果一个模型在稀疏条件下：

- bbox 性能下降不大
- target_status 性能下降不大
- reappearance 恢复能力仍然较强

那么可以认为它具备更强的序列认知记忆能力。

## 10. 指标体系建议

为了与传统 tracking benchmark 区分，我们建议采用“基础定位指标 + 认知指标”的双层设计。

### 10.1 基础定位指标

保留传统指标，作为底线参考：

- Success / AUC
- Precision
- Normalized Precision

这样可以保证 benchmark 与 tracking 社区常用评价方式兼容。

### 10.2 目标状态指标

建议加入：

- `Target State Accuracy`
- `Target State Macro-F1`
- `Absent False Alarm Rate`
- `Reappearance Recovery Rate`

### 10.3 环境状态指标

建议加入：

- `Environment State Accuracy`
- `Environment State Macro-F1`
- 多标签环境分类的 mAP 或 F1

### 10.4 序列认知记忆指标

建议加入：

- `Memory Consistency Score`
- `State Transition Consistency Score`
- `Sparse-to-Dense Performance Retention`
- `Long-gap Recovery Score`

这些名字后续可以再打磨，但逻辑上要成立：

- 单帧判断能力
- 环境理解能力
- 跨帧记忆能力

三者共同构成认知跟踪评测。

## 11. 与相关评测工作的对齐方式

从方法论上看，这个 benchmark 应该尽量对齐当前视频大模型、多模态大模型评测工作的常见范式，而不是完全按传统 tracking benchmark 的写法来做。

常见做法通常包括：

- 基于已有公开数据集构造新任务
- 通过筛选、重组、子集化来形成评测单元
- 引入新的结构化标签或维度标签
- 统一模型输入输出协议
- 设计多个互补指标，而不是只看单一分数

因此，我们的方案在方法论上是合理的：

- 数据不一定新，但任务定义是新的
- 标注不一定全重做，但关键标签和协议是新的
- 模型比较不只看一个数，而是看多维能力画像

这比单纯“拿几个模型跑 tracking score”更像一个完整 benchmark。

## 12. 第一阶段交付物

为了让 benchmark 尽快落地，第一阶段建议只交付以下内容：

### 12.1 三个子任务的数据集确定

明确：

- 短时跟踪使用哪个数据集
- 长时跟踪使用哪个数据集
- 全局跟踪使用哪个数据集

### 12.2 关键帧版本

为三个数据集分别构建关键帧索引或关键帧标注版本。

### 12.3 标签映射协议

明确：

- `target_status` 映射规则
- `environment_status` 映射规则
- 哪些标签来自原标注
- 哪些标签来自派生规则

### 12.4 统一评测格式

明确：

- 输入格式
- 输出 JSON 格式
- 指标计算脚本输入格式

### 12.5 第一版 baseline

在统一协议下，先跑若干 VLM baseline，哪怕当前先从 Qwen-VL 系列开始也可以。

---

## 13. 当前建议的结论

当前最合理的 benchmark 路线是：

**沿着短时跟踪、长时跟踪、全局跟踪三类任务各选一个代表数据集，基于已有公开标注构建关键帧版本，并新增目标状态、环境状态和序列认知记忆三类评测维度，形成一个面向视觉大模型复杂认知能力的跟踪 benchmark。**

这条路线有几个优点：

- 符合 tracking 任务的发展脉络
- 符合大模型 benchmark 的常规构建方式
- 成本相对可控
- 有清晰的创新点
- 便于后续扩展到多模型、多协议和训练型工作

如果后续要进一步细化，最优先应补两份文档：

- `label_mapping.md`
- `evaluation_protocol.md`

前者解决“标签怎么来”，后者解决“分数怎么算”。这两份文档补上后，benchmark 的主体方案就基本闭合了。
